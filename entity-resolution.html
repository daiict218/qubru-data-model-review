Entity Resolution — the resolution key and fallback for all 44 entities

How the pipeline must recognise that an entity already exists before creating it. Companion to Data Model v3.1.

Universal rule. Before creating any node: (1) compute its resolution key from the extracted data; (2) look up an existing node with that key; (3) if found → reuse it and attach the new evidence; (4) if not found → create.

44 entities 6 strategy groups 22 have a fallback 6 never deduplicate

How to read this table

  1. Resolution key (green) — the field combination that answers “does it already exist?”. This is what the pipeline looks up first. Fields joined by + must all match; alternatives are separated by or.
  2. Fallback (amber) — what to use when the resolution key is absent from the document (for example a medical report with no registration number). A fallback fires on absence, not on disagreement.
  3. Strategy — the deduplication pattern to implement. Six patterns cover all 44 entities.
green resolution key amber fallback D1 source domain in v3.1

Highest priority: Policy (by policy_number) and Claim (by claim_number) are the graph anchors. If they do not resolve, the N documents of one case create N policies and claims, and the graph fragments.

Group 1 Strong natural key Have a unique number or code in the document. Resolve by that identifier before creating. Highest priority — they anchor the graph.
Broker D1 (broker_code) or (license_number) party_id Resolve by natural key Internal code or regulatory license. Link to its Party.
Claim D6 claim_number (policy_id + loss_date + insured_item_id) Resolve by natural key claim_number is unique. The N documents of one claim (FNOL, peritaje, settlement) must all resolve to the same Claim. HIGHEST PRIORITY.
Coverage D2 (product_version_id + coverage_code) (product_version_id + name) Resolve by natural key coverage_code unique within version (TPL, PD, THEFT, PI).
Endorsement D5 endorsement_number (policy_txn_id) Resolve by natural key Carrier-assigned endorsement number.
Policy D5 policy_number (account_id + inception_date + product_version_id) Resolve by natural key policy_number is unique (already declared in the model). Anchors the whole lifecycle — if unresolved, every document fragments the graph. HIGHEST PRIORITY.
Product D2 product_code (name + jurisdiction) Resolve by natural key product_code unique (e.g. AUTO-CO). Master data — few, stable instances.
ProductVersion D2 (product_id + version_code) (product_id + effective_from) Resolve by natural key version_code unique within product (e.g. 2024.1).
Quote D4 quote_number (submission_id + quote_type + quoted_premium) Resolve by natural key Quote has its own number. Distinguish revisions (R1, R2) by quote_type.
RatingMatrix D2 matrix_code (product_version_id + effective_from) Resolve by natural key Matrix code (e.g. RM-AUTO-CO-2024.1).
RegulatorRequest D9 reference_number (authority + received_date + subject) Resolve by natural key The oficio has a number (e.g. 2025-0342-DSF).
UWRuleset D2 ruleset_code (product_version_id) Resolve by natural key Ruleset code (e.g. UW-2024.1).
Group 2 Natural key with context Own identifier but needs a fallback (normalized name / parent) when the ID is absent from the document.
Actor D1 party_id (humans) or (actor_kind + model + role) for agents normalized display_name Resolve via Party A human Actor resolves by its Party (party_id). Do NOT create independent Actor and Party — link them. Repeated advisors must resolve to the same Actor.
InsuredItem D5 type-conditional (see note) (policy_id + item_number) or (policy_id + item_description) Resolve by natural key Key depends on item_type — see the LOB note below. For vehicle : vin (globally unique). For property : registry/cadastral ID. For equipment : serial number. For cargo : shipment ref. item_number ('7 of 14') is NOT unique across policies.
Party D1 (country + id_type + id_number) normalized legal_name + country (alias table) Composite key + alias fallback THE CRITICAL CASE. NIT/Cédula is the key. The model already declares 'unique within id_type+country' but it isn't enforced. Documents with no ID → resolve by normalized name. Use merged_into_party_id to merge already-created duplicates.
Group 3 Resolve by parent + type No own number. Identified by whom they belong to plus their type. Composite key.
Account D1 (party_id + product_line) (party_id) para cuenta única Resolve by parent An organization has one commercial account per line. Resolved via its Party.
ClaimCoverage D6 (claim_id + policy_coverage_id) none Resolve by parent A claim affects each coverage once.
ClaimInvolvement D6 (claim_id + party_id + involvement_type) none Resolve by parent Juan as driver in claim X, once. involvement_type distinguishes roles (same party could be driver then witness — different cases).
ClaimItem D6 (claim_id + insured_item_id) (claim_id + damage_description) Resolve by parent Damage to one item in a claim, once.
CommissionSchedule D2 (broker_id + product_version_id) none Resolve by parent One commission schedule per broker per version.
Container D3 (kind + product_id + jurisdiction) none Resolve by parent Few containers, stable. Master container per deployment.
Exposure D5 (policy_id + insured_item_id + period_start) none Resolve by parent Temporal measurement — one per item per period.
Insured D1 party_id none Resolve by parent The insured role resolves by Party. Don't create a new Insured if the Party already has one.
PartyRelationship D1 (from_party_id + to_party_id + relationship_type) none Resolve by parent One typed relationship between two parties, once.
PolicyCoverage D5 (policy_id + coverage_id) none Resolve by parent The theft coverage of policy X exists exactly once.
PolicyTransaction D5 (policy_id + txn_type + effective_date) none Resolve by parent One transaction per type per effective date.
RetentionSchedule D9 (jurisdiction + doc_type + product_id) none Resolve by parent Retention rule per jurisdiction+type. Few, stable.
Submission D4 (account_id + product_id + submitted_date) (broker_id + insured_id + effective_date_requested) Resolve by composite key One submission per quoting attempt. Distinguish remarkets/renewals by submitted_date. NOTE: don't confuse the Quote with the Submission — saw cases of Quote classified as Submission.
Group 4 Event-like Dated events. High risk of duplicating the same event from different documents. Signature = type + date.
ClaimEvent D6 (claim_id + event_type + event_date) (claim_id + event_type + document_reference) Resolve by event signature HIGH duplication risk: the same peritaje mentioned in 2 documents must NOT create 2 events. Date+type is the signature. (Seen in tests: 'Peritaje completado' x3).
EvidencePackage D9 (claim_id o policy_id + regulator_request_id) none Resolve by event signature One package per request/decision.
Payment D6 (settlement_id + paid_to_party_id + amount + payment_date) payment_reference Resolve by event signature If payment_reference exists (transaction number) use it as strong key. DECISION: historical loss-run payments (prior insurer) should NOT be materialized as Payments.
Reserve D6 (claim_id + claim_coverage_id + reserve_date + reserve_type) none Temporal — no dedup across dates CAUTION: reserves are temporal BY DESIGN. Each adjustment on a different date is a LEGITIMATE new record — do NOT deduplicate across dates. Only avoid creating the same-date reserve twice.
ReviewCase D9 (artifact_id + case_type + related_*_id) none Resolve by event signature One review case per reviewed item.
Settlement D6 (claim_id + claim_coverage_id + settlement_type + settled_amount) (claim_id + settlement_date) Resolve by event signature One agreement per coverage. Distinguish partial settlements by type.
Group 5 Content-hash dedup Already supported in the model via content_hash. Same file → same node. Just activate it.
Artifact D7 content_hash (SHA-256) (original_filename + file_size_bytes) Resolve by content hash ELEGANT AND ALREADY IN THE MODEL: the same PDF uploaded twice has an identical hash → same Artifact. Just USE it.
ReferenceDocument D3 content_hash (SHA-256) (doc_type + version_label + title) Resolve by content hash Same hash → same reference document. NOTE: don't confuse submission attachments with ReferenceDocuments (seen in tests).
Group 6 Do not deduplicate / special rule Each instance is unique by nature (signals, provenance, audit) or has its own rule (one active per parent).
AgentOutput D8 no key — always create none No dedup — always create Each agent run produces a new output. The temporality is the value.
AuditEntry D9 no key — always create none No dedup — always create Each human/system action is a unique audit record.
DatasetResolution D7 (artifact_id) última vigente none One active per artifact One active resolution per artifact.
DocumentClassification D7 (artifact_id) última vigente none One active per artifact One active classification per artifact; re-classifications mark the previous one as superseded.
Pattern D8 no key — always create none No dedup — always create Each detection is a finding with its sample_n and date.
PatternMember D8 (pattern_id + member_id) none Resolve by parent Avoid listing the same member twice in a pattern.
ProvenanceNode D9 no key — always create none No dedup — always create Each knowledge operation generates its own receipt. Never deduplicate.
Recommendation D8 no key — always create none No dedup — always create Each recommendation is unique.
Signal D7 no key — always create none No dedup — always create Each extraction is a unique event with its provenance. Multiple signals of the same type from different documents are valid (accumulated evidence).

InsuredItem — the key depends on what the item is (type-conditional)

InsuredItem has no single natural key. Which field identifies it depends on item_type. Note that item_number (“7 of 14”) is not unique across policies.

item_typeNatural identifierReal-world example
vehiclevinGlobally unique VIN. Already a named column in the model.
propertyregistry / cadastral IDA building has no VIN. In Colombia: matrícula inmobiliaria or cédula catastral. Address is a weak fallback (inconsistently written), like a name is for a Party.
equipmentserial numberManufacturer serial number.
cargoshipment / bill-of-lading referenceCargo is often transient, so it may resolve by (policy_id + description).
all typespolicy_id + item_numberFallback when no strong identifier is present in the document.
